# Plugin Platform

> English | [简体中文](plugins.zh-CN.md)

> Related: [Architecture](architecture.md) · [Domain Model](domain.md) · [Roadmap](roadmap.md) · [AGENTS.md](../AGENTS.md)

> [Architecture §7](architecture.md#7-plugin-system-libsplugin) describes the two plugin runtimes and how the server calls plugins. This document describes how plugins reach what Jellyfin's plugins reach, apart from channels and live TV: the server's API, events, HTTP routes, tasks, a data folder, remote devices and the remaining provider types. It also describes DLNA, which Mavio ships as a first-party plugin built on them, and the provider types acquisition adds. The work is phase P13 (platform) and P14 (DLNA) of the [Roadmap](roadmap.md), and P15 to P18 for the acquisition providers.

---

## 1. Principles

* **Contracts, not internals.** Jellyfin plugins run in the server's process and take any internal service by dependency injection. Mavio plugins keep their isolation: they reach the server only through its public Connect API and the contracts of `libs/proto/mavio/plugin/v1`. What a plugin may do is declared in its manifest and granted by the host.
* **One contract, both runtimes.** Every capability works the same for WASM and process plugins, except where the WASM sandbox cannot (§9).
* **Additive.** New capabilities, manifest fields and host services are added to `mavio.plugin.v1`; nothing published changes meaning.

## 3. Host API

### 3.1 Scopes
A manifest lists the services a plugin may call in `permissions.api`, as `<package>.<Service>` for every method or `<package>.<Service>:read` for the methods marked `NO_SIDE_EFFECTS`, such as `mavio.library.v1.ItemService:read`. Any other call is `permission_denied`.

### 3.2 Who a Plugin Acts As
* By default a plugin acts as itself: an administrator within its scopes, with no user of its own, so methods about the caller's own state (user data, playbacks) fail with `failed_precondition`.
* With `permissions.act_as_users`, a request may name a user in the `Mavio-User` header; it then acts as that user, under the user's policy, as if the user made it. Disabled and unknown users are `unauthenticated`.
* A device controller (§7) acting as a user may also name one of its devices in `Mavio-Device`, so that the playbacks it starts belong to that device's session. A device it does not list, or a device without a user, is `failed_precondition`.

### 3.3 Transport
Plugins reach the API at the base URL `http://mavio.host` with the client `guest.HostClient()` returns, which carries both Connect calls and the plain HTTP media routes:
* **WASM**: a request to `mavio.host` through `http_fetch` is served in process by the server's handler tree instead of the network.
* **Process**: the host serves its handler tree on a second socket in the plugin's private socket folder, named by `MAVIO_HOST_SOCKET`.

The channel a request arrives on identifies the plugin: the host drops any credentials it carries (`Authorization`, cookies), so a plugin cannot borrow a user's session. The host API socket of a process plugin requires the same per-start token as the plugin's own socket.

### 3.4 Limits
* A WASM plugin's call into the host API runs while its own call holds one of its instances; a host call that needs the same plugin waits for another instance and fails at the call timeout when none comes free.
* WASM plugins receive host API responses whole, up to 64 MiB, so server streams such as `EventService.Subscribe` are for process plugins only.

## 4. Events

### 4.1 Event Types
Events are `mavio.plugin.v1.Event`: ID, type, time, title, message, item, user and attributes. Positions are in milliseconds.

| Type | When | Activity log |
| :--- | :--- | :--- |
| `user.login`, `user.login_failed` | Sign-in | Yes |
| `user.created`, `user.updated`, `user.deleted`, `user.password_changed` | Account changes; the event's user is the account, the `by` attribute the user who changed it | Yes |
| `apikey.created`, `apikey.revoked` | API keys | Yes |
| `settings.updated`, `backup.created` | Administration | Yes |
| `ai.credential_changed`, `ai.login_started` | AI provider credentials (§8.15); `provider` attribute | Yes |
| `plugin.installed`, `plugin.updated`, `plugin.configured`, `plugin.uninstalled`, `plugin.failed` | Plugins; `plugin.failed` when a plugin fails to start | Yes |
| `task.completed`, `task.failed` | A task's run ends; `task` attribute (the task's ID in `TaskService`), and `plugin` for plugin tasks, whose message is the run's | Failures only |
| `playback.started`, `playback.stopped` | A playback starts or stops, also when it expires or its sign-in ends; `playback`, `session` and `position` attributes, and `played` when it stops | Yes |
| `subtitle.downloaded`, `subtitle.download_failed` | Subtitle downloads; `provider` and `subtitle` attributes | Failures only |
| `item.added`, `item.updated`, `item.removed` | Library changes, after their transaction commits; `library` attribute. They are worked out only while a plugin consumes them | No |
| `library.scanned` | A library scan ends; `library` and `succeeded` attributes | No |
| `userdata.changed` | A user's item state changes: `played`, `favorite`, `position` | No |

### 4.2 Delivery
* `NOTIFIER` plugins receive the activity log events as before.
* `EVENT_CONSUMER` plugins receive the events whose types match the patterns of `permissions.events` (`item.added`, `item.*` or `*`), through `EventConsumerService.Consume`, in batches of up to 100 events gathered for one second.
* Each plugin has its own queue of up to 10,000 events; a failed batch is retried three times with backoff, and events beyond the queue's size or past their retries are dropped with a warning. Delivery is at most once per plugin, in order.

## 5. HTTP Routes
* A plugin declaring `HTTP_HANDLER` serves every method under `/plugins/{id}/`, at the root and under the base URL, also while it waits for its configuration. The host strips the prefix and delivers the request to the handler the plugin registers with `guest.HandleHTTP`, with `X-Forwarded-For`, `X-Forwarded-Host` and `X-Forwarded-Proto` describing the client's request. Inside the plugin, routes live under a reserved path apart from its Connect services.
* Authentication is the plugin's: routes are reachable without a token, as DLNA renderers and OAuth callbacks require. When a request carries a valid bearer token, the host removes it and adds `Mavio-User-Id`, `Mavio-User-Name` and `Mavio-User-Admin`; it strips those headers from requests without one. Other `Authorization` headers reach the plugin unchanged.
* Every response carries `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups`, so that a page a plugin serves runs in an opaque origin and cannot read the server origin's storage.
* A manifest may name a page among its routes as `config_page`, a path relative to `/plugins/{id}/` such as `settings`, which clients open next to the form the configuration schema describes.
* **Runtimes**: process plugins are reached by a streaming reverse proxy over their socket, which presents the plugin's token in `Mavio-Plugin-Token` so that the request keeps its own `Authorization`. WASM requests are buffered and bounded by the call timeout, at most 16 MiB each way; the ABI request envelope carries the method and query after the body, which earlier guests ignore.

## 6. Tasks and Data Folder
* **Tasks**: a manifest of a `TASK_RUNNER` plugin lists tasks (ID, name, description, interval of at least a minute, timeout). They appear in `TaskService` as `plugin:{plugin}:{task}`, with the plugin's ID, and run as `plugin.task` jobs on a worker of their own, calling `TaskRunnerService.RunTask`: on their interval from the plugin's start, each run queuing the next, or on demand. A task's timeout, at most six hours and one hour when unset, replaces the WASM call timeout for that call. Scheduled runs of a plugin that is not ready are skipped; runs of tasks that are gone are dropped.
* **Data folder**: each plugin has a writable folder `<home>/plugin-data/<id>` (`--plugin-data-dir`), kept across upgrades, included in backups and deleted on uninstall. Both runtimes tell plugins its path in `MAVIO_PLUGIN_DATA` (`guest.DataDir()`); WASM plugins see it at `/data`.
* **Host's operating system**: both runtimes name the host's operating system and its version in `MAVIO_HOST_OS` (`guest.HostOS()`), lowercased as Servarr applications name them in their User-Agent, such as `ubuntu 22.04`: on Linux from the `ID` and `VERSION_ID` of `/etc/*release`, on macOS from the system version property list, on Windows from `RtlGetVersion`.

## 7. Remote Devices
* A `DEVICE_CONTROLLER` plugin, which also needs `permissions.act_as_users`, keeps its devices up to date with `HostService.SetDevices`: ID, name, product and the kinds of commands each takes. Every plugin may call `mavio.plugin.v1.HostService` without a scope; other callers are `permission_denied`. Its `GetServerInfo` tells the server's name, version, HTTP and HTTPS ports and base URL, for the URLs a plugin gives devices on the local network.
* The server lists every device as a session of `SessionService.ListSessions`, with the plugin's ID and no user, online while the plugin lists it, shared: every signed-in user sees them, may send them commands and learns of their changes. A device listed again keeps its session; devices the plugin no longer lists, or of a plugin that stops, are gone, and so are their playbacks.
* Commands play items as a queue, pause, resume, stop, skip within the queue, seek, show a message, or set the volume and mute. `SendCommand` to a device calls `DeviceControllerService.SendCommand`, within 30 seconds, with the command, the device and its session, and the user who sent it; a command the device does not take is `failed_precondition`, and the plugin's error is the sender's. The plugin carries it out acting as that user and device (§3.2): it starts and reports the playback through `PlaybackService` with the device's capabilities, so the device's session shows what it plays.

## 8. Provider Capabilities

### 8.1 Image Providers
`ImageProviderService.GetImages` returns remote images (kind, URL, size, language, rating) for a lookup. `MetadataService.ListRemoteImages` lists them with the metadata providers' images, and refreshes take images of kinds an item lacks from them in provider order.

### 8.2 External IDs
A manifest declares external ID kinds in `external_id_kinds`: key, display name, the media kinds that carry them (persons included), and an optional URL template such as `https://trakt.tv/movies/{id}`. The built-in kinds cover TMDB, IMDb, TheTVDB, TVmaze, AniDB, AniList, aniSearch and MusicBrainz; a started plugin's kinds follow them, and a key already listed is not redefined. `MetadataService.ListExternalIdKinds` lists them, optionally for one item kind; `ItemService.GetItem` and `GetPerson` return `external_urls`, the pages of the item's or person's IDs, with each ID escaped as a path segment.

### 8.3 Local Metadata and Savers
* `LOCAL_METADATA` plugins declare file name patterns in the manifest's `local_metadata_files`, such as `*.yaml`. While refreshing an item, the host reads the matching files in the item's folder (the item itself for folders such as series), at most 16 of up to 1 MiB each, and passes their names and contents, with the name of the item's media, to `LocalMetadataService.ReadMetadata`, which returns metadata the way providers do. Local metadata takes precedence over providers, after NFO; refreshes that replace metadata ignore it, as they do NFO.
* `METADATA_SAVER` plugins receive an item's saved metadata, with its credits and remote images, in `MetadataSaverService.SaveMetadata` and return files (name relative to the item's folder, contents); in libraries saving local metadata the host writes them there with the NFO file, unless one of them leaves the folder, replaces the media or exceeds the limits above.

### 8.4 Metadata Processors
`MetadataProcessorService.ProcessMetadata` receives the merged metadata of an item at the end of a refresh, with the credits of the most trusted source, before it is saved, and returns metadata to apply over it: set fields replace the item's, except locked ones, and people replace its credits unless the cast is locked. Processors run in order, each seeing what the ones before did; one failing changes nothing.

### 8.5 Lyrics Providers
`LyricsProviderService.SearchLyrics` (track name, artists, album, duration, external IDs) returns lyrics with their IDs, and `DownloadLyrics` returns them as LRC when synced and plain text otherwise, at most 1 MiB. `MetadataService.SearchRemoteLyrics` and `DownloadRemoteLyrics`, for administrators, search every lyrics provider and save the chosen lyrics beside the track as `.lrc` or `.txt`, replacing its other lyric files; lyrics that do not parse, or synced lyrics without times, are refused. Refreshes download them for tracks without lyrics in libraries that enable a lyrics provider (§8.11).

### 8.6 Resolvers
`ResolverService.Ignore` returns which entries of a folder to leave out; `ResolverService.Resolve` may claim a folder and return the items it holds, as the built-in resolvers do, before them. Resolvers run on every folder of a scan, so they are WASM plugins only.

A request carries the folder (library kind, library folder, path, what its containing folder resolved to, the containing season's number) and the names of its entries. Every resolver's `Ignore` runs first, in plugin order; then the first resolver that claims the folder resolves it, and folders no resolver claims go to the built-in resolvers. A claimed folder may be an item itself (`folder_item`: a series, a season, an album, a photo album) and holds items made of its files, each with its name, year, indexes, external IDs and the further files of a stacked video, and the subfolders to scan next with what the folder is to them. Items must be of kinds scans find and name existing entries; extras and versions stay with the built-in resolvers. A resolver that fails or returns an invalid result makes the folder count as unreadable: the scan keeps the items already stored under it.

### 8.7 Intro Providers
`IntroProviderService.GetIntros` (item ID, kind and name, user ID) returns the IDs of items to play before an item for a user, such as its local trailers or a pre-roll, which plugins find through the host API. `PlaybackService.ListIntros` returns them in provider order, each once and at most 20, leaving out the item itself, unknown items, items that do not play and items the user cannot access; a provider failing leaves the others' picks.

### 8.8 Image Generators
`ImageGeneratorService.GenerateImages` (item ID, kind and name, the kinds of images it lacks) returns images of some of those kinds, JPEG, PNG or WebP of at most 8 MiB each. At the end of a refresh, the kinds no source gave are asked of the generators in order, each kind once; the images are kept in the metadata folder (`<id[:2]>/<id>/generated/<kind>.<ext>`) and come after every other source. Later refreshes keep them without asking again, a replacing refresh makes them anew, and one is removed once another source gives its kind. Images of kinds not asked for, or that are not images, are refused.

### 8.9 Media Source Providers
`MediaSourceProviderService.GetMediaSources` returns extra media sources of an item, each an ID, a name and an http(s) URL. When a playback starts, the server asks every media source provider, probes each URL with ffprobe (a probe is reused for an hour, a failure for five minutes) and gives the source a stable ID derived from the plugin, the item and the plugin's ID. Playback decisions consider them after the item's files: the server direct plays them by redirecting to the URL and remuxes or transcodes them with ffmpeg reading the URL; their bitrate is not capped as a local file's is. Item details list only the item's files; `PlaybackService.ListMediaSources` lists the files and then the media source providers' sources, marked `remote`, so that a client can choose one to play.

### 8.10 Password Reset
`AuthService.ForgotPassword` makes an eight-digit one-time PIN for a user who signs in with a password and passes it, with the user's ID and name and its expiry, to the `PasswordResetService.StartReset` of the plugin chosen in the server settings (`password_reset_plugin`), which delivers it its own way (e-mail, chat). It answers alike whether or not the user exists, delivering in the background. The server keeps only the PIN's hash, in memory, for 30 minutes; a new PIN replaces the user's previous one, and five wrong PINs end it. `AuthService.ResetPassword` with the PIN sets a new password and ends the user's sessions. Without a chosen plugin, `ForgotPassword` fails with `FAILED_PRECONDITION`.

### 8.11 Provider Order per Library
A library stores, per capability (metadata, images, subtitles, lyrics, segments, episode listers), which providers it uses and in which order, by plugin ID (`LibrarySpec.provider_order`). An unset list means every ready provider in plugin ID order; an empty one means none; IDs of plugins not running are skipped. Refreshes, metadata and image searches, subtitle and lyrics searches and downloads, and media segment jobs ask only the library's providers, in its order.

With `download_lyrics` set, a refresh of a track without a lyric file beside it searches the library's lyrics providers and saves the first lyrics that download, as an administrator's download would.

The lookup of an episode whose file holds several carries the last one's number as `episode_number_end`; metadata providers then describe the episodes as one, their names and overviews joined by ` / `, as Jellyfin's TmdbEpisodeProvider does. `scraper-tmdb` and `scraper-servarr` do so.

Beyond what items keep, metadata providers tell what a title's page shows, as Seerr does: a movie's budget and box office takings and its release in cinemas, a series' next air date, where the title is in its making and run (`production_status`), the countries it was produced in by code, the number of votes its rating counts, its genres, keywords and studios by the IDs discovery filters by (`genre_refs`, `keyword_refs`, `studio_refs`), and the services streaming it by subscription in the lookup's country. A title's page looks a title up with `all_credits`, for its whole cast and crew, each job credited; libraries keep only the directors, writers and producers. The host does not store them; `DiscoverService.GetTitle` returns them. `scraper-tmdb` takes them from TMDB's details and watch providers. It also gives a title's YouTube trailers in `remote_trailers`, which items keep, from TMDB's videos in the lookup's language and English.

### 8.12 Acquisition Providers
Acquisition ([Architecture §13](architecture.md#13-acquisition-libsacquire)) adds five provider types, all gathered by the server, never called by one another:
* `EPISODE_LIST_PROVIDER`: `EpisodeListProviderService.ListEpisodes` lists a series' seasons and episodes, numbered in the lookup's `display_order`, with their absolute numbers and metadata, and the external ID (`provider`) that identifies them; refreshes of series make virtual items of the episodes the series lacks from the first of the library's episode listers that knows it ([Domain Model §4.8](domain.md#48-virtual-items)). `scraper-tmdb` provides it: in the aired order, or by the first TMDB episode group of the display order's type, its groups as seasons. `scraper-servarr` provides it from Sonarr's SkyHook, always numbered as TVDB numbers them, as Sonarr numbers releases and files whatever the display order; `scraper-tmdb` finds an episode with a TVDB ID by that ID, so that it gives such episodes TMDB's metadata whatever their numbers.
* `DISCOVERY_PROVIDER`: `DiscoveryProviderService` lists movies and series to discover. `ListCatalogs` declares the provider's catalogs, each of a kind (trending, popular, upcoming, top rated, recommendations or similar titles of a title, a list curated elsewhere such as a chart, or the movies of a collection), for movies, series or both, with the filters and orders it takes; `Discover` returns a page of a catalog's titles, with their external IDs, dates, genres, images and ratings, filtered by genre, studio, network, keyword, watch provider, original language, release dates, runtime, rating, vote count and content rating; `ListFilterValues` lists the values of a filter, or those matching a query; `SearchTitles` finds movies and series by name, a page at a time, or answers UNIMPLEMENTED when the provider does not search; `GetPerson` tells of a person by their external IDs, with their biography, dates and the movies and series they play in and work on, each once with its roles joined, the most voted first, or answers UNIMPLEMENTED when the provider does not know people; `GetCollection` tells of a collection of movies by its external IDs, with its overview, images and movies in release order, or answers UNIMPLEMENTED when the provider does not know collections. `DiscoverService` marks what the server has, wants or was asked for. `scraper-tmdb` provides it as Seerr uses TMDB: trending titles of the day, popular and upcoming titles through TMDB's discover endpoints, top rated titles, recommendations and similar titles, and the movies of a collection (a catalog of the collection kind, taking a `tmdb_collection` external ID), and searches as Seerr does, with the prefixes `tmdb:`, `imdb:`, `tvdb:` and `year:`, tells of people from their TMDB details and combined credits, their biography in English when it has no translation, and of collections from TMDB's. `scraper-servarr` provides Radarr's movie lists: TMDB's trending and popular movies, IMDb's Top 250 and popular movies, StevenLu's lists by rating, and recommendations of a movie; it does not search or know people or collections.
* `RATINGS_PROVIDER`: `RatingsProviderService` tells a movie's or series' ratings elsewhere than TMDB: `GetRatings` takes its kind, external IDs, English name and year, and returns each rating with its source (Rotten Tomatoes' critics' or audience score, IMDb's), score, votes, page and whether Rotten Tomatoes certifies it fresh, none when it does not know the title. `DiscoverService.GetRatings` asks every ratings provider, as Seerr's ratings beside a title's TMDB score. `plugins/ratings` provides it as Seerr does, without a key: Rotten Tomatoes' scores of movies and series through the search Rotten Tomatoes' site uses, matching the name and year by Seerr's scores, and IMDb's ratings of movies by their IMDb IDs from Radarr's metadata service.
* `SCENE_MAPPING_PROVIDER`: `SceneMappingProviderService` tells how releases name and number series otherwise than their episode lists, for matching releases to series and episodes: `ListSceneMappings` lists the titles releases use for series or some of their seasons, with the season they number, the title to search indexers with and a regular expression releases must match, each from a source of the provider whose mappings replace those it listed before; `ListDailySeries` lists the series whose releases are named by air date; `GetSceneNumbering` lists how releases number a series' episodes where they number them otherwise than its episode list. `scraper-servarr` provides it from Sonarr's services (scene mappings and daily series) and XEM (titles and numbering by TVDB), as two sources; when one is unavailable it lists the other's alone.
* `INDEXER_PROVIDER`: `IndexerProviderService` searches indexers. `ListDefinitions` lists the kinds of indexers the provider implements, sites or protocols such as Newznab, with the settings each takes, secrets marked; the plugin's configuration lists the indexers configured from them, which `ListIndexers` lists with their capabilities (Newznab's search parameters and categories), whether they are left out after failing, and the settings the server's decisions and grabs use (tags, the languages of MULTi releases, and for torrent indexers the required flags, minimum seeders, seed ratio, seed time, season pack seed time and whether torrents whose hash is blocklisted are refused when grabbing) and the download client the indexer's releases are always sent to; `TestIndexer` checks an indexer's settings; `SearchReleases` searches indexers for movies, series or text, by IDs, title, season and episode, in Newznab categories, within age and size limits, and reads their recent releases when given nothing to search by, returning the releases (with the origin, source, container, codec and resolution of those whose indexer tells them) and the indexers that failed; `GetReleaseFile` fetches a release's torrent file or NZB, or the magnet link its download link leads to, and refuses NZBs that are not valid; `ReleaseService` searches every ready indexer provider, keeping their indexers for an hour, until the plugin restarts or is configured again. `plugins/indexers` keeps what sites give it across restarts (cookies, Newznab capabilities, API tokens) with each indexer's status in its data folder. `plugins/indexers` provides it.
* `DOWNLOAD_CLIENT_PROVIDER`: `DownloadClientProviderService` sends releases to download clients. `ListDownloadClientDefinitions` lists the kinds of clients the provider implements with the settings each takes, as indexer definitions do; the plugin's configuration lists the clients configured from them, each with a category for movies and one for series, which `ListDownloadClients` lists with their protocol, priority, tags, host (for remote path mappings), whether they prefer torrent files to magnet links and whether they are left out after failing; `TestDownloadClient` checks a client's settings, returning warnings for what does not stop it from working (a missing category, a development version); `AddDownload` sends a client a torrent file, magnet link or NZB, of a movie or series, recent or not, with the seeding its indexer asks for, whether it is a full season (which Pneumatic refuses), what the release and its movie or series are (quality, languages, release group, indexer, year, collection, studio, title slug, which Flood adds as tags) and the hashes of the torrents blocklisted for them (a torrent whose hash the release did not give is refused when its hash is among them), and returns the download's ID, failing as unimplemented when the client takes no magnet links, for the server to send the torrent file instead, and as a failed precondition when the client refuses the release; `ListDownloads` lists the downloads in the clients' categories with their state, sizes, ratio and output path, and what each client tells of itself (its output folders, whether it removes completed downloads, its sorting); `GetDownload` reads a download again before it is imported; `RemoveDownload` removes one, with its files if asked; `MarkDownloadImported` moves an imported download to the client's category for imported downloads. `DownloadService` sends each release to a client of its protocol, as Radarr's DownloadClientProvider: those sharing a tag of the movie or series, else those without tags; of those, the indexer's own client when it has one; else, of those not left out after failing (or of all when all are, unless the release was kept pending until a client is back), those of the first priority, in turn. `plugins/download-clients` provides it; it keeps the seed limits grabs gave each torrent in its data folder (`seeds.json`), for torrents to keep them across restarts, and lists as many history items of usenet clients as its `history_limit` says.

Both network-facing providers are process plugins: indexers and download clients are at addresses the administrator configures, which a WASM manifest's `http_hosts` cannot list, and indexers need proxies and long-lived sessions.

### 8.13 Subtitle Providers
`SUBTITLE_PROVIDER` serves subtitle acquisition ([Architecture §14](architecture.md#14-subtitle-acquisition-libsacquiresubtitles)) as Bazarr's providers serve it. `SubtitleProviderService.ListSubtitleProviders` lists the providers the plugin implements with the settings each takes (secrets marked), whether each is enabled and whether it is throttled, and until when; `SearchSubtitles` takes a video's description (names, alternative titles, IDs, season, episode and absolute number, year, release name with its source, release group, resolution, codecs, edition and streaming service, frame rate, file name, size and OpenSubtitles hash) and several languages with their forced and hearing-impaired wishes, and returns candidates with their provider, release names, language, flags and the properties the provider found matching, which the server scores; `DownloadSubtitle` returns one, extracted from its archive. Failures carry their kind (too many requests, download limit, service unavailable, authentication, configuration, a subtitle to blocklist), from which the plugin throttles the provider. `plugins/subtitles` provides it as a process plugin: its sites are behind logins, cookies, Cloudflare and captchas, some are self-hosted at addresses the administrator gives, and it keeps sessions, throttling state and captcha services' accounts in its data folder.

Subtitle providers read no audio: subtitles transcribed from a video's audio come from the server's transcription source, with the recognizers of `SPEECH_TO_TEXT` plugins (§8.16, [Architecture §14.5](architecture.md#145-translation-and-transcription)).

### 8.14 Subtitle Translators
`SUBTITLE_TRANSLATOR` translates subtitles ([Architecture §14.5](architecture.md#145-translation-and-transcription)) with translation services, as Lingarr's do. `SubtitleTranslatorService.ListSubtitleTranslators` lists the translators the plugin implements with their settings, whether each is enabled, how many cues each takes at once, whether it keeps SubRip's markup and the source and target languages it translates (BCP 47, none for any), by which the server orders its chain of translators; `TranslateSubtitleLines` takes a translator, the source and target languages, the cues' text (plain, or as SubRip holds it for translators keeping markup) and a description of the movie or episode, and returns as many translations, an empty one keeping its cue, with what to credit. The server parses the subtitle, sends its cues in batches and writes the translation. `plugins/subtitles` implements Lingarr's translation services: DeepL (its API with the account's key, fifty cues a request, the free API for keys ending `:fx`) and LibreTranslate (a server's URL and optional key, 25 cues a request), whose languages are listed by the service and kept for a day, and, as the GTranslate library Lingarr uses reaches them without keys, Google Translate (the endpoint of its browser extensions, with its request token), Bing Translator (its page's endpoint with the page's credentials, read again hourly), Microsoft Translator (its Android app's API, requests signed as the app signs them) and Yandex.Translate (its Android app's API), a cue per request, four at once, in batches of twenty, between the languages Lingarr lists for them. Languages are matched to the service's codes by BCP 47 (`zh` is `zh-Hans`, `pt` is `pt-BR`). Rate limits and unavailable services are reported as such for the server to retry; rejected keys, exhausted quotas and languages a service lacks are not retried, and any cue failing fails its batch.

### 8.15 AI Gateway and Agent Sessions
`AI_GATEWAY` reaches AI model providers on the server's behalf, so that no feature of the server holds a credential. `AiGatewayService.ListAiProviders` lists the providers with how each authenticates (API key, OAuth login, whether the login is a subscription's such as Claude Pro or ChatGPT Plus), the credential stored and whether it can be used; `ListAiModels` lists their models with their context window, reasoning, image input and prices. `SetAiApiKey` stores or removes a key, and `LogoutAi` removes a credential. An OAuth login runs in the plugin: `StartAiLogin` starts it, `GetAiLogin` returns what it shows (a page to sign in on, a device code, progress), what it asks and whether it ended, `WatchAiLogin` streams the same each time it changes until the login ends, and `AnswerAiLogin` answers it, such as with the address the browser was sent to when the provider's redirect cannot reach the plugin; clients follow it through the server. `CompleteAi` asks a model for one answer, as JSON matching a schema when the request gives one, with the tokens used and their cost; `StreamAi` streams the answer's text and reasoning as they come, then the same response. Failures carry Connect codes: unavailable for failures worth retrying (rate limits, overload, network), unauthenticated without a usable credential, not found for an unknown provider or model, invalid argument when the context overflows.

`AGENT_SESSION` keeps conversations with a model durably (`AgentSessionService`): created with a model and instructions, listed, read with their messages, continued with `SendAgentMessage`, whose request ID makes a retry the same message, or `StreamAgentMessage`, which streams the answer so far as it grows, then the answer, and deleted. Each message and answer is stored before it is returned.

Conversations of the assistant ([Assistant §6](assistant.md#6-ai-path)) also carry:
* **Remote tools**: a conversation is created with the declarations of the server's tools — name, description, JSON Schemas of the arguments and the result, and a TypeScript declaration — which the model calls and the server runs. `WatchAgentToolCalls` streams to the server the calls waiting, then each new one, with its ID, conversation, tool and arguments, nested in a code mode script or not; `SubmitAgentToolResult` answers a call with the model's text, the structured result and whether it failed. A call waits, durably, until it is answered or its conversation is deleted; after the plugin restarts the same call is listed again with the same ID, and the server answers it from its record of the calls it ran without running it again.
* **Code mode**, when the conversation is created with it: the model also has pi-durable's `codemode` tool, whose JavaScript calls the conversation's tools in a QuickJS sandbox, each call a nested call reaching the server as any call does.
* **Messages added without an answer**: `AddAgentMessages` adds a user's message and its answer, as the assistant's fast path made them, without asking the model.
* **Memory**: a conversation created with a memory key (the server's user ID) has the plugin's `remember`, `forget` and `recall` tools and the key's memories in its instructions, within a budget; `EndAgentSession` ends a conversation and starts a background task that consolidates the conversation into the key's memories. `ListAgentMemories`, `UpdateAgentMemory`, `DeleteAgentMemory` and `DeleteAgentMemories` (all of a key's) let the server show and manage them.

`plugins/agent` provides both as a TypeScript process plugin compiled by Bun, on [pi-ai](https://github.com/earendil-works/pi) and pi-durable: every provider pi-ai supports, with API keys, OAuth logins (subscriptions included; clients warn of the risk and leave the choice to the administrator) and the providers its configuration adds, served by OpenAI-compatible APIs such as Ollama's; credentials are kept in its data folder (`credentials.json`, readable only by the server's user), and sessions in a SQLite database there, so an answer in progress goes on after a restart. pi-durable keeps a conversation's entries for good: the plugin records the sessions deleted (`deleted-sessions.json`) and, when it next starts, removes their conversations, with those they own and their documents, before opening the database. A schema's answer comes through a tool the model calls, with constrained sampling where the provider has it. Remote tools are pi-durable tools declared safe to replay, which hand their call to the server and wait for its result in a task document; code mode is pi-durable's code mode extension with its QuickJS sandbox; memories are a pi-durable document family keyed by memory key, searched by `recall` with pi-durable's BM25 search, and deleting a key's memories purges them with its conversations' documents.

### 8.16 Speech Recognition and Synthesis
`SPEECH_TO_TEXT` recognizes speech for the assistant ([Assistant §8](assistant.md#8-speech)) and transcribes subtitles ([Architecture §14.5](architecture.md#145-translation-and-transcription)). `SpeechToTextService.ListSpeechRecognizers` lists the recognizers the plugin has configured, each with its ID, name, languages (BCP 47), the longest audio it takes, and whether it streams, gives timestamps, detects the language, translates to English and takes hints. `TranscribeSpeech` transcribes audio read from a URL of the host API (`/speech/audio/{token}`, 16 kHz mono 16-bit PCM aligned with the start of the video, its `stream` parameter picking the audio stream and `seconds` only the first seconds), or given in the request when it is short, into text, or into segments with their times when asked, in a language or detecting it, transcribing or translating to English; `DetectSpeechLanguage` detects the language of the first 30 seconds. `StreamSpeech`, a bidirectional stream, takes PCM as it is recorded with the language and hints, and returns partial and final text; a recognizer that does not stream answers once the stream ends. Failures carry Connect codes as the AI gateway's do.

`TEXT_TO_SPEECH` speaks the assistant's answers. `TextToSpeechService.ListVoices` lists the voices of the services configured, each with its ID, name, languages and a sample's text; `SynthesizeSpeech` streams the speech of a text with a voice in a format the request names (Opus in Ogg, MP3, or PCM).

`plugins/voice` provides both as a Go process plugin: its configuration lists the services, each a kind with its address, key (a secret) and model — whisper-asr-webservice, the OpenAI-compatible transcription and speech APIs, Deepgram, Azure Speech, Google Cloud's speech services, Volcengine's and Alibaba Cloud's speech services, and ElevenLabs — and the plugin names their recognizers and voices `<plugin>/<id>`. whisper-asr-webservice is Bazarr's Whisper provider moved from `plugins/subtitles` with its language mapping, its two timeouts and its test cases; streaming services are reached over their WebSockets, and the others are given each utterance whole.

## 10. DLNA (`plugins/dlna`)
DLNA is a first-party process plugin: it needs UDP multicast, which WASM has no sockets for, and long-lived listeners. It is built for every platform the server is and bundled in the container image (§10.6).

### 10.1 Capabilities
`HTTP_HANDLER` (descriptions, control and event URLs, media), `DEVICE_CONTROLLER` (Play To), `EVENT_CONSUMER` (`item.*`, for content updates), and the host API with `act_as_users` and the scopes `LibraryService:read`, `ItemService:read` and `PlaybackService`.

### 10.2 Media Server
* **Discovery**: SSDP on 239.255.255.250:1900 on every interface: `NOTIFY` alive and byebye, answers to `M-SEARCH` for the root device, `MediaServer:1`, `ContentDirectory:1`, `ConnectionManager:1` and `X_MS_MediaReceiverRegistrar:1`. The description URL is the server's address on the interface the request came in on, with its HTTP port and base URL from `HostService.GetServerInfo`.
* **Content**: `ContentDirectory` `Browse` and `Search` as the configured user, over the user's libraries, folders, series, seasons, albums, artists, playlists and collections, as DIDL-Lite; `SystemUpdateID` follows library events, announced by GENA.
* **Media**: each `res` URL is the plugin route `media/{item}/{file}`, with the profile in `?profile=` or matched by request headers. A request starts a playback for the renderer's profile through `PlaybackService` (direct play, or a progressive remux or transcode, since most renderers take no HLS); requests for the same user, item, profile and start share a playback, dropped after four idle minutes. The host's media route is proxied with ranges and the DLNA headers renderers expect (`contentFeatures.dlna.org`, whose `DLNA.ORG_OP` is 01 for direct play and 10 for time seek, and `transferMode.dlna.org`); `TimeSeekRange.dlna.org` restarts a transcode at the time given. Subtitles go as a `res` or `CaptionInfo.sec` pointing at `subtitles/{item}/{file}` (SRT) when the profile takes them, else are burned in. Images go through `images/{id}?size=`, as JPEG thumbnails or large images.

### 10.3 Play To
* The plugin searches for `MediaRenderer:1` devices every five minutes and follows their announcements, reads their descriptions and registers each as a device (§7) with the profile matching it. Renderers listed in the configuration, such as those on other subnets, are read from their description URLs.
* Commands map to `AVTransport` and `RenderingControl`: play (`SetAVTransportURI` with the route `play/{playback}/stream.{ext}` and its DIDL-Lite, then `Play`), pause, resume, stop, seek (`REL_TIME` for direct play; a transcode restarts at the position), next and previous within the queue it keeps, volume and mute. The plugin polls the transport every second and reports progress at most every five seconds; a renderer stopping within ten seconds of the end has played the item, and the next one starts. A renderer playing another URI, or failing three polls, stops its playback.

### 10.4 Device Profiles
Built-in profiles cover Samsung, LG, Sony and Panasonic televisions, Kodi and VLC, with a generic profile for the rest. A profile has a `name`; `match` rules, regular expressions on `friendly_name`, `manufacturer`, `model_name`, `model_number` and request `headers`, every field set matching; the `capabilities` it takes, as a `ClientCapabilities` in JSON; and its quirks: `time_seek`, `caption_info`, `subtitle_res`, and `mime_types` replacing the MIME types of containers. Profiles in the configuration replace the built-in one of their name and are tried before the others.

### 10.5 Configuration
The `user` whose libraries are served (required), the `server_name` shown, `media_server` and `play_to` (default on), the `interfaces` to use (default every interface up with multicast and IPv4), `announce_interval_minutes` (default 30), `ssdp_port` (for tests), `renderers` (extra description URLs) and `profiles`.

### 10.6 Packaging
`tools/plugindist` builds the plugin for Linux, macOS and Windows on amd64 and arm64 and packs each as a catalog zip of `manifest.json` and the executable, with the other first-party plugins ([Development §7](development.md#7-releases-and-versioning)). The container image ships the plugin in its plugin seed folder (architecture document §12); SSDP multicast reaches a container only on the host network.
